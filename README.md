## 1. Что за проект

`Library Inventory Management System` — модульное консольное приложение (CLI) на Java для
управления книжным фондом библиотеки. Записи о книгах хранятся **в оперативной памяти**
с использованием коллекций Java (`HashMap` для быстрого поиска по ключу и `ArrayList` для
вывода списка). Проект собирается через Maven и следует принципам объектно-ориентированного
программирования.

Проект небольшой — несколько Java-классов, один автор, последний коммит добавил набор
тестов на JUnit 5 и исправил граничные случаи бизнес-логики.

## 4. Чего не хватает

Вопросы, на которые я не нашёл ответа при изучении проекта:

1. **Как собрать и запустить приложение.** В README указан Maven как инструмент сборки, но
   нет ни команд `mvn`, ни требований к версии JDK помимо «JDK 8 или выше», ни инструкций
   по запуску. Точку входа (`Main.java`) пришлось определять по структуре проекта.
2. **Полный список пунктов меню.** В README возможности CRUD (добавление, просмотр/поиск,
   изменение, удаление) описаны на высоком уровне, но не показано само интерактивное меню,
   точные приглашения к вводу и ожидаемый формат данных.
3. **Что происходит при некорректном вводе.** README упоминает «валидацию ввода и обработку
   исключений» для нечисловых вариантов и пустых строк, но не описывает точные сообщения
   об ошибках и поведение при восстановлении.
4. **Где и как хранятся данные.** В README указано, что хранение **в оперативной памяти**,
   но не объясняется, что все записи о книгах теряются при завершении приложения, и не
   сказано, планируется ли файловое хранение или поддерживается ли оно.
5. **Как запустить тесты.** Набор тестов на JUnit 5 есть, но нет инструкций по их запуску
   через Maven (`mvn test`) или интерпретации результатов.

> Пункт 4 остался выясненным лишь частично — README подтверждает хранение в памяти, но не
> говорит, является ли это осознанным проектным решением или временным ограничением.
> Связаться с автором для уточнения возможности нет.
